# Tag/Caption File Separation Feature

## Overview

TagGUI now separates tags and captions into different files, allowing you to generate and maintain both types of content without losing either. You can also easily switch between viewing tags and captions in the UI.

## File Types

### Three-Tier File System

1. **`.tags.txt`** - Explicit WD tags (comma-separated)
   - Generated by WD Tagger or MultiPersonTagger in tag mode
   - Takes priority when both `.txt` and `.tags.txt` exist

2. **`.caption.txt`** - Natural language captions (multi-line)
   - Generated by VLM models or MultiPersonTagger in caption mode
   - Independent from tag files

3. **`.txt`** - Legacy format (backwards compatible)
   - Used when no `.tags.txt` file exists
   - Manual edits save to this file by default

### Loading Priority

```
Tags: .tags.txt > .txt (fallback)
Caption: .caption.txt (independent)
```

## UI Features

### Interactive View Switching

At the bottom of the **Image Tags** dock, you'll see clickable labels:

```
View tags (image.tags.txt) | View caption (image.caption.txt)
```

**Visual Indicators:**
- **Active view**: Blue text, bold, no underline
- **Inactive view**: Grey text, underlined (clickable)
- **Hover**: Pointer cursor indicates clickability

### View Modes

#### Tags View (Default)
- Shows: Tag input box + tag list
- Window title: "Image Tags"
- Displays: Editable tag list with token counter
- File info: Shows which tags file is loaded

#### Caption View
- Shows: Caption text viewer
- Window title: "Image Caption"
- Displays: Read-only multi-line caption
- File info: Shows caption file source

**Note**: Caption view is only available when a `.caption.txt` file exists for the image.

## Auto-Captioning Behaviour

### Model Output Types

Different models save to different files automatically:

| Model Type | Output Type | Saves To | Example |
|------------|-------------|----------|---------|
| WD Tagger | Tags | `.tags.txt` | `1girl, long hair, blue eyes` |
| VLM Models | Captions | `.caption.txt` | `A young woman with long hair...` |
| MultiPersonTagger (LoRA mode) | Tags | `.tags.txt` | `person1, tags, person2, tags` |
| MultiPersonTagger (Fine-tune mode) | Captions | `.caption.txt` | `sksA: [description]\nsksB: [description]` |

### Manual Editing

When you manually edit tags in the UI:
- Saves to whichever file was originally loaded
- `.tags.txt` if it exists
- Otherwise `.txt`

## Example Workflow

### Scenario: Preparing Dataset for Both LoRA and Full Fine-Tuning

1. **Generate tags for LoRA training:**
   ```
   Run WD Tagger → Creates image.jpg.tags.txt
   ```

2. **Generate captions for fine-tuning:**
   ```
   Run MultiPersonTagger (fine-tune mode) → Creates image.jpg.caption.txt
   ```

3. **View and verify:**
   - Click "View tags" to see: `1girl, long hair, blue dress, smile`
   - Click "View caption" to see: `sksA: A young woman with long blonde hair wearing an elegant blue dress, smiling warmly at the camera.`

4. **Use in training:**
   - **LoRA training**: Use `image.jpg.tags.txt`
   - **Full model fine-tuning**: Use `image.jpg.caption.txt`

Both files coexist peacefully! 🎉

## Migration Notes

### Existing Projects

No migration needed! The system is fully backwards compatible:

- Existing `.txt` files continue to work as before
- Tags are loaded from `.txt` if no `.tags.txt` exists
- No files are automatically converted
- New auto-captioning saves to appropriate file type

### Converting Existing Files

If you want to convert existing `.txt` files to `.tags.txt`:

1. Simply re-run WD Tagger or tag-based models
2. New `.tags.txt` files will be created
3. Original `.txt` files remain untouched
4. Tags will now load from `.tags.txt` (higher priority)

## Technical Details

### Image Dataclass Changes

```python
@dataclass
class Image:
    path: Path
    dimensions: tuple[int, int] | None
    tags: list[str] = field(default_factory=list)
    caption: str | None = None  # NEW
    tags_file_type: str = '.txt'  # NEW - tracks which file was loaded
    thumbnail: QIcon | None = None
```

### Model Output Type

All auto-captioning models now have an `output_type` attribute:
- `'tags'`: Saves to `.tags.txt`
- `'caption'`: Saves to `.caption.txt`
